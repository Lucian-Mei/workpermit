| 项 | 内容 |
|---|---|
| 编制 | 高级项目经理 |
| 日期 | 2026-08-29 |
| 依据 | 用户 15 点需求 + 《EHS-Ⅱ-008 承包商安全控制程序 D03》（仅取业务逻辑，**不导入 FOR/文件编号**） |

## 1. 需求归并：端到端业务流

将 15 点需求归并为一条主流程（编号对应原文需求点）：

```
①内部员工登录 → 申请作业票（常规/危险；危险可关联常规票拉取字段，避免重复输入）
      │  填基础信息
      ▼
②提交 → 生成承包商邀请（邮件 + 二维码，二维码含于邮件）→ 发送承包商
      ▼
③承包商免登录打开链接 → 填监护人信息、作业内容（施工方案）→ AI JSA → 识别风险、定控制措施 → 提交
      ▼
④进入审批（建议：直接到申请部门主管，详见 §10.1）
      ▼
⑤审批通过 → 邮件通知申请人与承包商（含批准信息、作业代码、培训二维码）
      ▼
⑥承包商作业人员提前完成培训考核 → 入厂扫码签到（输作业码+姓名+身份证）→ 作业/培训校验
      ▼
⑦校验通过 → 放行入厂，状态「进行中」；全部签出 → 状态「已暂停」
      ▼
⑧首次进厂 → 现场交底（员工 + 承包商负责人共同，员工登录完成，承包商负责人签字；打印由员工电脑端）
      ▼
⑨交底签字 + 打印（方式 A/B 择优，见 §10.2）
      ▼
⑩作业开展 → 开启每日现场检查任务（每天 1 次）
      ▼
⑪危险作业：重复上述流程 + 危险作业单独检查要求（动火定时巡视等）
      ▼
⑫危险作业双态：挂靠常规票（子任务） / 不挂靠（独立任务），见 §10.3
      ▼
⑬作业完成 → 人员签出 → 申请人点击「完成」；或到期→申请人「续期」→重走审批
      ▼
⑭危险作业资质：按类型/法规要求作业证（焊工证/吊装证/制冷证…），JSA 时提示勾选危险作业
      ▼
⑮危险票审批：有常规票基础 → 申请部门主管 → EHS → 工程部经理（3 级）
```

## 3. 数据模型与关键实体关系

### 3.1 实体关系图（文字 ER）

```
workPermits（作业票·单表）
  ├─ isHazardous（false=常规 / true=危险）
  ├─ linkedRoutineId ──► workPermits（危险票挂靠的常规票，自引用）
  ├─ contractorInviteToken / contractorEmail（承包商邀请）
  ├─ entryQrToken / trainingQrToken / workCode（入厂/培训/作业码）
  ├─ jsas / safetyMeasures / riskHazards（JSA+风险+控制措施）
  ├─ approvalChain（审批链快照）
  ├─ guardianSignatures（危险票监护人双签）
  └─ 1─┬─N workPermitTrainings（培训记录，改挂 workPermitId）
       ├─N certificateOcr（作业证，workPermitId）
       ├─N safetyBriefings（交底，改挂 workPermitId）
       ├─N inspectionRecords（日常巡检，workPermitId）
       ├─N workPermitChecks（危险作业单独检查，workPermitId）
       └─N entryRecords（入厂签到/签出，workPermitId）← 新增
```

### 3.2 关键实体（改造/新增明细）

| 实体 | 关键字段 | 说明 |
|---|---|---|
| `workPermits`（作业票） | 见方案B §4 | 合并申请单后承载全部字段；新增 `contractorEmail`、`contractorInviteToken`、`contractorInviteExpiresAt`、`contractorSubmittedAt`、`renewalCount`、`renewalParentId` |
| `workPermitTrainings`（培训） | 改 `workPermitId`（替代 applicationId）+ `testResult`/`signCompletedAt`/`validUntil`（有效期） | 入厂校验依据：**合格且在有效期内直接放行，无需重复考核** |
| `certificateOcr`（作业证） | 已有：`workPermitId`/`issuer`/`ocrStatus`/`ocrFields` | 扩展 `certType`（焊工/吊装/制冷…）；**系统按作业内容自动判断是否必须**，默认可上传、判断为必须时强制 |
| `safetyBriefings`（交底） | 改 `workPermitId` + `points`/`signatures` | 员工+承包商负责人共同交底 |
| `inspectionRecords`（日常检查） | 改 `workPermitId`（替代 applicationId）+ `result`/`photo` | 每日 1 次 |
| `workPermitChecks`（危险检查） | 已有 `workPermitId`/`checkSlot`/`unlockAt` | 动火 0h/1h/3h 定时巡视 |
| `entryRecords`（入厂）★新增 | `workPermitId`/`personName`/`idCard`/`entryAt`/`exitAt`/`status`(in/out) | 签到/签出，驱动「进行中/已暂停」 |
| `actionTokens`（令牌） | 已有：`purpose`/`expiresAt`/`usedAt`/`multi` | 复用为免登录邀请/签字/培训令牌 |

## 4. 作业状态机与流转规则

### 4.1 常规作业票状态机（单表）

```
draft（员工填基础信息）
  → pending_contractor（已发邀请，待承包商填写）★新增
  → pending_review（承包商已提交，待审批）
  → reviewing（经理批准/承包商管理部门）
  → approved（已批准，发邮件+作业代码+培训二维码）
  → printed（执行中/进行中：首次入厂签到触发）
  ⇄ paused（已暂停：全员签出触发）
  → finished（完工待归档：申请人点完成/到期）
  → completed（已归档）
  （rejected / voided 分支保留）
```

### 4.2 危险作业票状态机（审批链随挂靠与否条件化）

```
draft → pending_contractor → pending_review（部门主管）
  → [不挂靠时 + 区域负责人] → ehs_reviewing（EHS工程师） → reviewing（工程部经理） → approved
  → printed ⇄ paused → finished → completed
（挂靠常规票时：入厂签到/状态继承常规票，见 §4.3）
```

- 审批链（关键）：
  - **挂靠常规票**（有 `linkedRoutineId`）：部门主管 → EHS工程师 → 工程部经理（3 级）。区域负责人已随常规票 2 级链（区域负责人 → 承包商管理部门）审批过，无需重复。
  - **不挂靠（独立危险作业）**：部门主管 → **区域负责人** → EHS工程师 → 工程部经理（4 级，新增区域负责人，杜绝"未经区域负责人即在其属地做危险作业"）。

### 4.3 危险票「挂靠 / 不挂靠」双态规则

| 维度 | 挂靠常规票 | 不挂靠（独立危险作业） |
|---|---|---|
| `linkedRoutineId` | 指向常规票 | null |
| 入厂签到 | **继承常规票**（不单独签到，避免"无人单独签到导致状态混乱"） | **独立签到**（凭危险票作业码） |
| 看板 | 常规票为主卡片，危险票为子任务（折叠，不占独立主卡片） | 独立主卡片 |
| 状态 | 随常规票状态联动 | 独立状态机 |
| 风险识别 | 常规票已识别危险作业，JSA 可复用 | **强制完整 JSA + 加强风险识别**（AI 强制 + 更多检查项） |
| 审批链 | 部门主管 → EHS → 工程部经理（3 级；区域负责人已随常规票审批） | 部门主管 → **区域负责人** → EHS → 工程部经理（4 级） |
| 统计计数 | 计 1 张票（workPermits 主记录） | 计 1 张票 |

> 结论：**统一以 `workPermits` 主记录计数**，不会造成统计混乱；"独立任务卡片"仅是看板展示维度。挂靠票状态继承、不挂靠票独立状态，规则清晰。

**挂靠/不挂靠在何处设置**：在**危险作业票申请表单**中，由申请人/承包商选择"是否挂靠常规票"——挂靠则从"已批准且未完成"的常规票中选一张（系统回填 `linkedRoutineId`/`linkedRoutineNo` 并自动拉取地点/区域/部门/作业人/内容等字段，避免重复输入）；不挂靠则留空，走独立危险作业流程。

### 4.4 续期规则
- 到期或申请人主动「续期」→ 生成新票（`renewalCount+1`，`renewalParentId` 指向原票），确认信息可修改 → 重走审批 → 新票生效。
- 复用 `replacedByPermitNo` 语义（作废重开/续期留痕）。

## 5. 权限与免登录链接安全设计

### 5.1 角色权限（沿用 PERMISSION_CATALOG + 新增）
- 员工/申请人：`work_permit:create`、查看自己的票。
- 审批人：`review`（部门主管）、`approve_ehs`（EHS）、`approve_mgr`（工程部经理）。
- 承包商负责人：**免登录**（无系统账号），凭一次性令牌。
- 承包商作业人员：**免登录**，凭作业码/培训码。

### 5.2 免登录令牌安全（关键设计）
| 机制 | 规则 |
|---|---|
| 令牌类型 | `actionTokens.purpose`：`contractor_invite`（填写）、`training`（培训考核）、`entry`（入厂）、`sign`（签字） |
| 一次性 vs 多次 | 邀请填写/签字=单次；培训考核/入厂=多次（同一票多人） |
| 过期 | 邀请 72h；培训码 3 天（复用现有 `trainingQrExpiresAt`）；入厂码作业周期内有效；培训考核有有效期（`validUntil`），效期内免考核直接进厂 |
| 校验维度 | 入厂：作业票编号 + 姓名 + 身份证，与受训名单比对 + 培训合格（在有效期内）才放行；身份证仅记录，不实名比对、不拍照 |
| 审计 | 令牌使用留痕（`usedAt`/操作人/时间/IP） |
| 防爆破 | 作业票编号 + 身份证号，输错限次 |

### 5.3 敏感信息
- 身份证号**仅记录 + 加密存储**，仅做受训名单比对（不实名比对、不拍照）；看板/打印默认脱敏（显示前 4 后 2 位）。
- 免登录页仅暴露该票必要字段（作业内容、风险告知），不暴露全库数据。

## 6. 邮件 / 二维码 / 扫码校验机制

### 6.1 邮件（nodemailer，需配 SMTP）
| 触发 | 收件人 | 内容 |
|---|---|---|
| 承包商邀请 | 承包商负责人邮箱 | 免登录填写链接 + **二维码（含链接）** |
| 审批结果 | 申请人 + 承包商 | 批准/驳回信息 + 作业代码 + 培训二维码 |
| 到期提醒 | 申请人 | 续期提示 |

- **SMTP 后置**：先不接真实 SMTP，采用"站内通知 + 二维码兜底"（二维码本身承载链接，不依赖邮件到达）；后续确定邮箱后再接，避免换邮箱返工。

### 6.2 二维码
| 码 | 载体 | 用途 |
|---|---|---|
| 邀请码 | 邮件内嵌 + 员工端展示 | 承包商免登录填写 |
| 培训码 | 审批后邮件 + 作业票打印 | 作业人员培训考核 |
| 作业票编号/入场码 | 现场（员工手机/看板） | 入厂签到/签出（作业票编号即作业码，**废弃独立 `workCode`/SG- 编号**） |

### 6.3 扫码校验（入厂）
```
扫入场码 → 输入作业票编号 + 姓名 + 身份证
  → 校验：编号存在且 approved/printed；姓名在受训名单；身份证匹配（仅记录，不实名）
  → 培训校验：testResult=合格 且 validUntil 未过期（效期内免考核直接放行）
  → 通过 → entryRecords.entryAt=now，状态「进行中」
签出 → 全员 exitAt 均填 → 状态「已暂停」
```

## 7. 看板与统计口径定义

### 7.1 看板展示
- **常规票**：独立主卡片。
- **危险票·不挂靠**：独立主卡片。
- **危险票·挂靠**：常规票卡片内的子任务（折叠），不占独立主卡片。

### 7.2 统计口径（统一，避免混乱）
| 指标 | 口径 |
|---|---|
| 作业票总数 | `workPermits` 主记录数（挂靠/不挂靠各计 1 张） |
| 进行中 | `printed` 且未 `paused`（含挂靠票随常规票） |
| 已暂停 | `paused`（全员签出） |
| 待审批 | `pending_review`/`ehs_reviewing`/`reviewing` |
| 日常检查完成率 | 应检查天数 vs 实查次数（inspectionRecords 按日去重） |
| 入厂人次 | entryRecords 去重（同票同人多次进厂计多段） |

## 10. 关键决策建议（回答问题 4 / 9 / 12）

### 10.1 问题 4：承包商提交后是否返回申请人确认？
**建议：直接进入审批（申请部门主管），不返回申请人。**
- 理由：申请人（内部员工）基础信息已填，承包商补充的施工方案/JSA 由审批人把关即可；返回申请人增加一轮无增值往返。
- 补偿：申请人收「承包商已提交」通知并可查看内容、必要时提出异议（可选"申请人预确认"开关，默认关）。

### 10.2 问题 9：交底签字方式（A 先手机签到后打印 vs B 先打印后签字）
**推荐方式 A：所有人员扫员工手机签到码 → 手机查看风险 → 页面签到 → 员工打印作业票。**
- 优势：免去人员往返打印机（十几分钟+）；签到即电子留痕（时间戳+签字）；打印件降为"事后归档/张贴"用途。
- 劣势与兜底：依赖现场网络/手机；离线时降级为 B（打印件现场补签，后补录）。
- B 的问题：打印机远、等待长、手写签字无法实时进系统。

### 10.3 问题 12：危险作业是否单独、是否统计混乱
**建议：危险作业始终为独立票，支持"挂靠/不挂靠"双模式。**
- 挂靠常规票：共享入厂签到/人员，看板作子任务折叠，状态继承常规票——避免"无人单独签到导致状态识别混乱"。
- 不挂靠（独立危险作业）：独立入厂签到、独立状态、独立主卡片；**强制完整 JSA + 加强风险识别**。
- **统计不混乱**：统一按 `workPermits` 主记录计数，"独立任务卡片"仅看板展示维度。默认鼓励挂靠（信息连贯、避免重复输入）。
- **审批链补齐**：挂靠票 3 级（部门主管→EHS→工程部经理，区域负责人已随常规票审批）；不挂靠独立危险作业 4 级（部门主管→区域负责人→EHS→工程部经理），**必须经区域负责人**，不得在其属地未审批即开工。

## 11. 需求澄清结论（已全部确认）

1. **培训考核有效期**：培训记录含有效期（`validUntil`）；效期内免考核直接进厂，过期需重新培训考核。
2. **挂靠/不挂靠设置位置**：危险作业票申请表单的"是否挂靠常规票"选择（挂靠→选已批准未完成的常规票并自动拉取字段；不挂靠→走独立流程，审批链 4 级含区域负责人）。
3. **身份证**：仅记录姓名+身份证号做培训名单比对，**不 OCR 实名比对、不拍照**。
4. **SMTP**：**邮件后置**，先"站内通知 + 二维码兜底"，后续确定邮箱再接（避免换邮箱返工）。
5. **作业代码**：**废弃独立 `workCode`/SG- 编号**，作业票编号（GWP-/HWP-）即作业码；作废后保留作废记录（`voided` + `voidReason`）。
6. **资质证**：系统按作业内容**自动判断是否必须**；证件默认承包商可上传，作业内容判断为"必须"时强制。

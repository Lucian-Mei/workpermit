1规划目标与一句话全景

★核心实体说明：作业申请单（数字化）

本流程围绕的唯一入口实体，即原纸质体系表单 FOR001 的电子化载体。

定位
所有作业的统一入口。原纸质 FOR001 作业申请单；电子化后以系统电子票号（SQ-/GWP-/HWP-）唯一标识，不再使用 FOR001 纸质编号
承载内容
① 内部填基本信息（作业对象/地点/承包商/负责人邮箱）② 承包商免登陆补充作业内容·方案·危险票 ③ 一次确认的 JSA 与风险清单 ④ 审批链与交底
与作业票关系
常规作业：申请单本身即作业票（draft＝申请，approved＝票）；危险作业：申请单下可挂靠对应危险作业票，各自走审批链
说明：FOR001 仅作为"纸质表单 → 电子数据"的演进溯源标注；其在打印文件与流程中均不再以编号呈现，由电子票号取代。后续如需纸质体系编号，由使用方自行补录。

责任：申请人 A
状态：draft

  • 作业需求（口头/工单）
  • 承包商库选择 contractors

生成邀请（邮件 + 二维码）
时机：阶段 1 完成后
责任：申请人 A
状态：awaiting_contractor
INPUT 输入
  • A 表基本信息（阶段 1 输出）
  • contractorEmail
  • SMTP 配置 systemConfig(email_config)
▶
PROCESS 处理
  • 写 T 表：purpose='contractor_fill'（危险票 'worker_fill'）、expiresAt=now+72h
  • 生成公开链接 /public/contractor-fill?token=…
  • 渲染二维码，卡片下方标注作业名称 + 计划日期

▶
OUTPUT 输出
  • 限时令牌记录（T 表）
  • 可复制链接 + 可下载二维码图片
  • 邮件（或降级提示）
  • A 表状态 → awaiting_contractor
退出准则：令牌生成且未过期；二维码可下载/复制；邮件已发或已给出降级提示（不阻塞流程）。
▼
STAGE 03 · 核心
承包商免登陆填写 + AI JSA
时机：承包商点链接/扫码
责任：CH / CW（无需登录）
状态：→ contractor_submitted
INPUT 输入
  • 令牌校验（有效期/是否已用）
  • A 表基本信息（只读，不可改）
  • 承包商填：作业内容、施工方案文件
  • 危险票另填：施工时间、作业人员、监护人、人员证书
  • 措施模板库 measure_templates（74 条）
▶
PROCESS 处理
  • ① ai.analyzeJsa 生成步骤级 JSA（每步含风险定级：高/中/低；仅做步骤级定级，不评整体作业风险等级）
  • ② 人工增删修订（不限次数）
  • ③ 可再分析（AI 累计 ≤3 次，以修订版为上下文续写）
  • ④ ai.analyzeBriefingHazards 自动派生风险清单＝JSA 汇总去重 ∪ 模板按类型补漏
  • ⑤ 承包商仅做增删/勾选确认（唯一人工录入）
▶
OUTPUT 输出（写 A 表）
  • content 作业内容 + 施工方案附件（files）
  • jsas = [{step,hazard,control,risk}]
  • riskHazards = [{hazard,consequence,measures[],checked}]
  • jsaAnalysisCount / jsaModifiedRound（审计）
  • 危险票：startTime,endTime,operatorNames,supervisorName + 证书
退出准则：jsas 每步 hazard/control 非空；riskHazards 至少 1 项 checked=true；危险票时间/人员/证书齐备。
▼
STAGE 04
公司复核 + 提交审批
时机：承包商提交后
责任：申请人 A
状态：→ pending_review
INPUT 输入
  • 阶段 3 全部产出
  • AI 复核提示（可选）
  • 是否挂靠常规票 linkedRoutineId（决定审批链分支，不再依赖整体风险等级）
▶
PROCESS 处理
  • 员工逐项核对承包商数据
  • 不合格 → 退回阶段 3（次数不重置）
  • 合格 → 按挂靠 / 不挂靠分支（危险票）生成审批链快照；常规票直接提交
▶
OUTPUT 输出
  • approvalChain 快照（seq/stage/roleKey/approverId）
  • 首节点 status=pending，待办推送
  • A 表状态 → pending_review
退出准则：审批链已生成且首节点待审；链路节点与"挂靠/不挂靠"规则一致。
▼
STAGE 05
审批会签（为告知书背书）
时机：提交后
责任：D / AR / E / M
状态：→ approved
INPUT 输入
  • 与打印件完全一致的告知书内容
  • jsas + riskHazards 中 仅 checked=true
  • 承包商资质、区域特殊要求
▶
PROCESS 处理
  • 部门主管：作业范围 / 承包商资质
  • 区域负责人（不挂靠）：该区域特有风险
  • EHS 工程师：控制措施充分性
  • 工程部经理：最终放行
  • 风险识别不足 → 退回重分析（分析↔审批闭环）
▶
OUTPUT 输出
  • 各节点 reviewOpinion / approvedAt
  • 全节点通过 → 状态 approved
  • 生成 W 表作业票 + qrCode
  • 告知书内容冻结为打印版本
退出准则：审批链全节点 approved；审批人所见 = 将打印内容；改内容须重新走审批（C8）。
▼
STAGE 06
安全交底 + 执行
时机：批准后、执行前
责任：交底人 B
状态：printed → finished → completed
INPUT 输入
  • 最终确认版：jsas + riskHazards[checked]
  • 作业内容与施工方案
  • 入厂人员名单 entry_registrations
▶
PROCESS 处理
  • 交底要点由终版自动派生，不重新识别危害
  • 现场逐条念读 → 勾选确认
  • 拍照 + 收承包商/监护/工人签字
▶
OUTPUT 输出（写 B 表）
  • points = [{text,checked}]（与打印件同源）
  • photos, signatures, content, briefedAt
  • 全勾选 → status=done → 允许转执行
  • 打印件：作业票 + 风险告知正文
退出准则：points 全部勾选 + 三方签字齐全；未完成交底不得转执行（C4）。

6AI 分析次数与产出规则（口径①②落地）

规则口径（已确认）实现要点
AI 次数上限 AI 分析总次数 ≤ 3
（首次 + 至多 2 次再分析）		 jsaAnalysisCount 每次调用 AI +1；达 3 后前端置灰 + 后端强校验拦截；提示"AI 分析次数已用完（3/3），可继续手工完善后提交"
人工修订 不限次数，不消耗 AI 次数 增删步骤、改写 hazard/control 自由；jsaModifiedRound 仅作审计记录，不设限
计数范围 按单张申请单累计，退回重填不重置 防止通过"退回—重填"绕过上限；计数随 A 表持久化
再分析语义 续写完善，非推倒重来 把承包商当前手工修订版 jsas 作为上下文喂给 AI，要求"补全缺失风险、修正不可行措施"，保留人工已确认内容
风险定级口径 仅 JSA 步骤级定级（高/中/低），不引入整体作业风险等级 风险只绑定到 JSA 的"步骤"，打印与审批均只呈现步骤级风险；riskLevel（整体等级）不进入流程与打印（C 校验收口）
产出语言风格 保持专业性，禁止口语化降级 使用规范安全术语（能量隔离、动火监护、气体检测、受限空间准入等），措辞为可核查的祈使句，术语后附具体执行动作与量化参数
✓ 正例（专业 + 可执行）
「能量隔离：断电、挂牌上锁（LOTO），并用万用表验电确认零能量」
「受限空间准入：作业前及作业中每 2h 检测 O₂ 19.5–23.5%、LEL <10%、H₂S <10ppm，全程留守监护人」
✗ 反例（两类均禁止）
过度口语化：「把电关了再干」——缺乏专业性与可核查性
纯术语无动作：「执行能量隔离」——现场无法照做、无法检查

这 8 条同时是验收标准。它们保证"系统更合理、风险控制更有效"是可度量的，而非主观判断。

9实施路线图（P0 → P3，13 个任务）

每任务 30–60 分钟可完成、带验收标准；每轮交付一个可点击演示的增量，预计 2–3 轮修订收敛。

P0 · 基础数据与服务≈3 天
  • P0-1 承包商邮箱字段（两表 + 申请页校验）
  • P0-2 邀请令牌（72h）与二维码（下方标注作业名称 + 日期）
  • P0-3 邮件邀请模板 + 未配置降级
出口：能对一张 draft 票生成可用邀请（链接 + 二维码），邮件可发或已降级。
P1 · 常规票承包商协同≈5 天
  • P1-1 免登陆填写公开页（只读信息 + 内容 + 方案上传）
  • P1-2 AI JSA + 次数上限 3（前端置灰 + 后端拦截）
  • P1-3 风险清单自动派生 + 一次确认
  • P1-4 提交进审批 + 交底引用终版
出口：一张常规票可由承包商全程免登陆完成填写并走到批准 + 交底。
P2 · 危险票与双审批链≈3 天
  • P2-1 作业人员填写页（时间/人员/监护/证书/内容/JSA）
  • P2-2 挂靠 3 节点 / 不挂靠 4 节点审批链分支
出口：危险票挂靠与不挂靠两条链均能按序会签至工程部经理批准。
P3 · 增强（可选）按需
  • P3-1 作业人员同步入厂名单 entry_registrations
  • P3-2 JSA 分析审计留痕页（谁、几次、何时）
  • P3-3 短信验证码增强（需短信服务）
出口：安全性与可追溯性增强，不影响主流程可用性。

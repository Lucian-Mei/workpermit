## 二、端到端正确流程（最终版）

```
员工填基础信息（不含作业内容/JSA！）→ 点「提交」
   → 系统自动生成二维码 + 链接（72h），发邮件（SMTP 未配则 emailSkipped 兜底）
   → 状态 awaiting_contractor（等待施工方填写）
   → 施工方扫码/点链接免登录填写：作业内容 + 施工方案 + JSA（AI≤3次）+ 风险勾选
        （危险票同一张邀请内再填：施工时间/作业人员/监护人/证书）
   → 提交 → contractor_submitted（施工方已提交）
   → [复核开关 ON] 员工复核（可退回重填）→ 提交审批
     [复核开关 OFF] 直接进审批
   → pending_review → 审批（只取 riskHazards 中 checked=true 项）→ approved → ...
```

### 阶段 1 —— 员工填什么（申请页，**没有作业内容/JSA**）

| 填 | 内容 |
|---|---|
| ✅ 员工填 | `jobName` 作业名称、`department` 部门、`building/floor/area/location` 地点、`planStart/planEnd` 计划时间、`operatorCount` 预计人数、`supervisorName/supervisorContact` 监护人、`permitType/type` 类型、危险票挂靠选择；承包商：`contractorUnit` 单位、`contractorHead` 负责人、`contractorPhone` 电话、`contractorEmail` 邮箱 |
| ❌ 员工**不填** | 作业内容 `content`、施工方案、JSA、风险清单（全部在阶段 3 由施工方填） |
| 退出条件 | 基础信息 + 承包商邮箱非空即可点「提交」 |

### 阶段 2 —— 提交即生成邀请（系统自动，员工可下载二维码）

- 员工点「提交」→ 系统自动：
  1. 生成 `contractor_fill` 令牌（72h）+ 公开链接 `/public/contractor-fill/:token` + 二维码
  2. 尝试发邮件给 `contractorEmail`（SMTP 未配 → `emailSkipped=true`，不阻塞）
  3. 状态 → `awaiting_contractor`
- 员工端展示：**二维码（可下载/打印）+ 链接（可复制）**，页面提示"请将二维码或链接发给施工方负责人"

### 阶段 3 —— 施工方填什么（免登录页，一张邀请含全部）

| 填 | 内容 |
|---|---|
| 只读 | 阶段 1 基础信息（票号/地点/时间/承包商信息），不可改 |
| ✅ 施工方负责人填 | `content` 作业内容；**[上传]** 施工方案；AI 生成 JSA `[{step,hazard,control,risk}]`（**≤3 次**，后端强校验；人工无限次修订）；风险清单 `riskHazards` 自动派生 → 勾选确认 |
| ✅ 危险票额外（同一张邀请内） | `startTime/endTime` 施工时间、`operatorNames` 作业人员、`supervisorName/supervisorContact` 监护、**[上传]** 作业人员证书 |
| 提交 | 校验：`jsas` 非空、`riskHazards` 有 `checked=true`、危险票时间/人员/证书齐 → `contractor_submitted` |

### 阶段 4 —— 员工复核（**可配置开关**）

- 开关 ON（默认）：承包商提交后 → 员工在系统内复核（可退回阶段 3）→ 确认后提交审批
- 开关 OFF：承包商提交后 → **直接**进审批（跳过复核）
- 开关位置：系统设置 → 流程管理（`systemConfig`，见 §六）

### 阶段 5 —— 审批
- 只取 `riskHazards` 中 `checked=true` 的项；常规 2 级；危险挂靠 3 级；危险不挂靠 4 级（含区域负责人）

## 三、状态机（最终版）

```
draft（员工填基础信息）
  → awaiting_contractor（提交即发邀请，等待施工方填写）★
  → contractor_submitted（施工方已提交，等待复核[开关ON] 或 直接审批[开关OFF]）★
  → pending_review（部门主管）→ [area_reviewing 不挂靠危险] → [ehs_reviewing] → reviewing → approved
  → printed（进行中）⇄ paused → finished → completed
  （rejected / voided 分支保留；驳回后允许重新邀请）
```

- 危险票挂靠：`pending_review`(部门主管) → `ehs_reviewing`(EHS) → `reviewing`(工程部经理)
- 危险票不挂靠：`pending_review`(部门主管) → `area_reviewing`(区域负责人) → `ehs_reviewing`(EHS) → `reviewing`(工程部经理)

## 五、验收口径（DoD）

- 员工申请常规票：表单**无**作业内容/方案/JSA；填基础信息+邮箱 → 点「提交」→ **自动出现二维码(可下载/复制)+链接**，状态变「等待施工方填写」
- 施工方无痕打开 → 填作业内容/方案 → AI JSA（第 4 次拦截）→ 勾选风险 → 提交 → 「施工方已提交」
- 复核开关 ON：员工复核后送审；OFF：直接送审
- 危险票：一张邀请内完成 方案/JSA/时间/人员/证书
- 审批人只见勾选风险项；全程无 404/500；前后端 tsc/build 0 错
- **旧数据已清理**，系统从干净状态启动

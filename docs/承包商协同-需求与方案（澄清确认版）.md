## 一、用户核心诉求（原话记录）

> "员工填写一部分后发送给承包商，然后承包商进行风险识别"
> "员工申请时**不需要填写作业内容（施工方案）**，这是由承包商去做的"
> "没有邮箱填写的地方，没有发送邮件和生成二维码"（→ 入口必须清晰可见）

一句话：**员工只填基础信息 → 发邀请（邮箱+二维码）→ 承包商免登录填作业内容/方案/JSA/风险 → 回传 → 审批**。

## 二、正确流程（阶段 1–6，字段归属权威，任何人不得改动）

```
阶段1 员工填基础信息（不含作业内容/方案/JSA！）
阶段2 员工点「发送邀请」→ 生成链接+二维码（72h）→ 状态 awaiting_contractor
阶段3 承包商免登录填写（作业内容/施工方案/JSA/风险确认）→ 提交 → contractor_submitted
阶段4 员工复核（可退回）→ 提交审批 → pending_review
阶段5 审批（只取 riskHazards 中 checked=true 项）
阶段6 交底（points 引用阶段3 终版，不重识别危害）
```

### 阶段 1 —— 员工填什么（申请页）

| 填 | 内容 |
|---|---|
| ✅ 员工填 | `jobName` 作业名称、`department` 部门、`building/floor/area/location` 地点、`planStart/planEnd` 计划时间、`operatorCount` 预计人数、`supervisorName/supervisorContact` 监护人、`permitType/type` 类型、危险票挂靠选择；承包商：`contractorUnit` 单位、`contractorHead` 负责人、`contractorPhone` 电话、**[新] `contractorEmail` 邮箱** |
| ❌ 员工**不填** | 作业内容 `content`、施工方案、JSA、风险清单 —— **全部由承包商在阶段 3 填** |
| 退出条件 | `jobName/地点/承包商单位/负责人/电话/邮箱` 非空 |

### 阶段 2 —— 发送邀请（员工申请流程中直接可见）

- 员工点「发送邀请」→ 系统生成 `contractor_fill` 令牌（72h）+ 公开链接 `/public/contractor-fill/:token` + 二维码
- 配置了 SMTP → 发邮件给 `contractorEmail`；未配置 → `emailSkipped=true`，页面显示链接+二维码兜底（**不阻塞**）
- 状态 → `awaiting_contractor`（等待承包商）
- 员工端要能看到：邮箱输入框（就在申请表单里）＋「发送邀请」按钮 ＋ 生成的链接/二维码/复制

### 阶段 3 —— 承包商填什么（免登录页，核心）

| 填 | 内容 |
|---|---|
| 只读 | 阶段 1 的基础信息（票号/地点/时间/承包商信息），不可改 |
| ✅ 承包商填 | `content` 作业内容；**[上传]** 施工方案；危险票另填 `startTime/endTime`、`operatorNames` 作业人员、`supervisorName/supervisorContact` 监护、**[上传]** 作业人员证书 |
| JSA | AI 生成 `[{step,hazard,control,risk}]` → 可二次 AI（**≤3 次**，`jsaAnalysisCount`，后端强校验）→ 人工无限次修订 |
| 风险清单 | 系统自动派生 `riskHazards`（JSA 危害去重 ∪ 措施模板补漏）→ 承包商**增删/勾选**确认（非从空白录入） |
| 提交 | 校验：`jsas` 非空、`riskHazards` 有 `checked=true` → `contractor_submitted` |

### 阶段 4 —— 员工复核

- 承包商提交后，员工在系统内复核（可退回阶段 3 重填）→ 确认后 `pending_review` + 生成审批链

## 三、状态机（权威，含新增状态）

```
draft（员工填基础信息）
  → awaiting_contractor（已发邀请，等承包商填写）★ 关键新增
  → contractor_submitted（承包商已提交，等员工复核）★ 关键新增
  → pending_review（部门主管）→ [ehs_reviewing] → reviewing → approved
  → printed（进行中）⇄ paused → finished → completed
  （rejected / voided 分支保留；驳回后可重新邀请承包商）
```

- 危险票挂靠：`pending_review`(部门主管) → `ehs_reviewing`(EHS) → `reviewing`(工程部经理)
- 危险票不挂靠：`pending_review`(部门主管) → `area_reviewing`(区域负责人) → `ehs_reviewing`(EHS) → `reviewing`(工程部经理)

## 六、验收口径（DoD）

- 员工申请常规票：表单**无**作业内容/方案/JSA，只有基础信息 + 承包商字段 + **邮箱** + **发送邀请**
- 点「发送邀请」→ 链接/二维码就地出现，可复制；状态变「等待承包商填写」
- 无痕打开链接 → 承包商填作业内容/方案 → AI JSA（第 4 次被拦截）→ 勾选风险 → 提交 → 状态「承包商已提交」
- 员工复核 → 提交审批 → 审批人只见勾选的风险项
- 全程无 404/500；前后端 tsc/build 0 错

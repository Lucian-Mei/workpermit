一、概念清理：只保留两类单据

名称（新）对应旧称定位说明
常规作业票（即申请单） 作业票申请单 一套常规作业的「总开关」：干什么、在哪干、谁干、什么时间、预计人数、是否含特殊作业。 常规作业票草稿（draft）即申请单，审批通过后即为作业票。不是两份独立单据，全程只有一个编号。
特殊作业票

关于「打印」：打印不与任何流程环节绑定，只是一个独立功能。原 printed 状态不再作为「进入现场执行」或「巡检校验」的前置条件。现场执行与每日巡检由作业票的「进行中 / 暂停」开关驱动（见第十节）。

三、审批链与审批人（删除风险分级）

删除风险分级开关与 evaluateRiskLevel 分级逻辑。你明确要求「不要风险分级功能」。特殊作业票不再按低/中/高风险走 2/3/4 级，全部走固定的默认审批流。系统设置中不再提供「风险分级审批」开关。

审批人如何确定

角色确定方式
区域负责人按作业区域确定（区域 → 负责人映射）。
承包商管理部门按申请人所在部门确定，即申请人部门的 leader。
申请部门主管特殊票首签人，即提交特殊票的申请人所在部门主管（多数情况下即承包商管理部门 leader）。
EHS 工程师安全环保部指定人员。
工程部经理工程部负责人。

常规作业票（GWP）固定审批链

①
区域负责人 → 承包商管理部门 → approved。
当「区域负责人 == 承包商管理部门 leader」时，系统自动跳过承包商管理部门节点，并做好备注。
注意常规票不经过 EHS；但在最终 approved 时，系统同步抄送 EHS（见第十一节邮件）。

特殊作业票（HWP/CSE/…）固定审批链

②
申请部门主管 → EHS 工程师 → 工程部经理 → approved。
任一环节驳回 → rejected，邮件通知申请人。

四、单据关系与流转总览

常规作业票（GWP，即申请单）

  • 草稿即申请单，审批通过后即为作业票，全程单号。
  • 可独立创建，也可由其他页面快捷入口跳转（均指向同一创建页）。
  • 一个常规票可触发 0~N 张特殊作业票。
  • 只有常规票生成 workCode 与培训二维码。

特殊作业票（HWP/CSE/…）

  • 必须从已批准且未完工的常规票发起（常规票状态 ∉ draft/pending_review/reviewing）。
  • 从常规票预填信息，可修改，不强关联。
  • 从其他页面进入时，需手动关联到某张已批准未完工的常规票。
  • 不生成 workCode；动火作业有特殊的 1h/3h 现场检查后流程。
关键顺序：
  1. 创建常规作业票（draft）→ 填写基础信息（含预计人数）→ JSA 分析 → 提交 → 审批 → approved。
  2. approved 后：立即生成 6 位 workCode 与培训二维码；下发培训二维码，承包商自行组织培训考核；可打印（打印为可选功能）。
  3. 作业人员入厂时校验一级安全培训，通过方可进场。
  4. 申请人/管理员点「开始」→ 作业票进入「进行中」→ 交底、巡检、签字、检查开始按日历日执行。
  5. 若含特殊作业：在常规票 approved 后开具对应特殊作业票，独立走固定审批链。
  6. 常规票完工（finished）→ 归档（completed）；特殊票同样 finished → completed。

五、常规作业票完整流程

1
创建常规作业票 GWP
入口：「作业票管理」列表的「新建常规作业票」；或任何页面的快捷入口。
原则：只能有一个总创建页面，其他路径都是链接到该页面并可选预填。
创建时填写：作业内容、作业位置、作业人、计划起止时间、预计作业人数、是否含特殊作业。
产物：草稿状态 draft，编号 GWP-YYYYMM-XXXX。
2
JSA 分析（强制环节） AI
输入具体作业内容 → AI 一键填写作业步骤 → 人工修改后保存 → AI 自动进行 JSA 分析 → 输出「风险 ↔ 措施」两列 → 申请人勾选/取消并最终确认（详见第七节）。
产物：JSA 分析报告、风险控制措施清单（风险 ↔ 措施两列）。
3
提交申请 硬拦截
校验项：
  • 作业内容、位置、作业人不空。
  • 常规作业周期 ≤ 7 天。
  • 若从常规票发起特殊作业（特殊票提交时），仅校验父常规票 ∉ draft/pending_review/reviewing。
  • 不校验一级安全培训（培训在入厂时校验，不在提交阶段强制）。
提交后：构建固定审批链，进入 pending_review，向审批人发审批邮件。
4
审批 硬流程
常规票固定链：区域负责人 → 承包商管理部门（同一人自动跳过并备注）。
全部通过后 → approved；通知申请人并抄送 EHS。
任一环节驳回 → rejected，邮件通知申请人。
5
批准后：生成码、下发培训、可打印
approved 后：立即生成 6 位 workCode 与培训二维码（显示在右侧卡片，见第十二节）。
下发培训二维码 → 承包商自行组织一级安全培训与考核。
打印为可选功能：仅 approved 后可打印，打印模板由系统管理员勾选可见模块；打印不改变流程状态，不触发「进入现场执行」。
6
现场执行（由「进行中/暂停」开关驱动）
申请人或管理员点「开始」→ 进入进行中（此状态驱动现场执行与巡检，不依赖打印）。
现场活动：
  • 安全交底：线上逐条勾选 + 承包商线上签字（挂在常规票上，一份）。
  • 每日巡检：自进入「进行中」起，每个已过日历日 ≥1 条，附照片（必选）。缺记录需补充说明。由「进行中/暂停」状态决定当天是否需要巡检（见第十节）。
  • 现场签字：作业人、监护人、相关责任人通过手机扫码签字。
  • 现场检查：作业前安全措施落实情况勾选，生成现场检查任务（现场作业台内）。
暂停：点「暂停」并填写原因 → 状态变暂停，EBoard 显示暂停；暂停期间免巡检；暂停记录含原因，在审批进度面板中体现。
7
完工 → 归档 硬拦截
finish：「进行中」期间的每日巡检齐全 + 现场签字完整。
archive：同上校验；workCode 按时间灰化/过期（计划时间到期自动变灰并打过期标签）；可选同步飞书多维表格。
终态：completed。

六、特殊作业票完整流程

1
创建草稿 HWP/CSE/…
入口：常规票详情「添加特殊作业票」；或作业票管理列表新建（选择类型）。
父常规票须已 approved 且未完工。
从其他页面进入时，需手动关联到某张已批准未完工的常规票（下拉选择）。
创建时从常规票预填：区域、位置、内容、作业人、监护人、时间等，可修改，不强关联。
2
填写与上传证书
必填：作业内容、位置、作业人、监护人（特殊票强制）。
证书要求：仅高处、动火、吊装、临时用电强制上传特种作业证；其余特殊作业不强制特种证，但需专项培训记录或操作证（如受限空间、动土、盲板抽堵）。
时限：危险作业 ≤ 24h，临时用电 ≤ 15 天。
3
提交申请 硬拦截
校验：必填项 + 时限 + 监护人 + 强制证书（四类）。
提交后走固定审批链（无风险分级）： pending_review（申请部门主管）→ ehs_reviewing（EHS 工程师）→ reviewing（工程部经理）→ approved。
每步向对应权限人发审批邮件；任一环节驳回 → rejected。
4
批准与现场执行
特殊票批准后 不生成 workCode（workCode 只在常规票上）。
现场执行：安全交底沿用常规票那份；每日巡检挂在特殊票自身（由自身「进行中」驱动）；现场检查必须完成。
动火作业特殊流程：
  1. 作业结束 → 作业人现场确认。
  2. 1 小时后 → 管理部门人员确认可离开。
  3. 3 小时内 → 管理部门人员持续监视；3 小时后做最终检查。
  4. 此最终检查不强制拍照（可结合烟感等结果确认）。
5
完工 → 归档
finish/archive 校验：每日巡检齐全 + 现场签字完整 + 现场检查完成。
特殊票不强制一级安全培训，但须校验直接作业人员和监护人的培训在效期内。

七、JSA 分析（AI 辅助·强制）

JSA 是作业票提交前的强制步骤。AI 作为辅助，帮助申请人把作业内容拆成可分析的步骤、识别风险、推荐措施，并输出可在现场交底时一一对应的「风险 ↔ 措施」清单。

1
输入作业内容
申请人填写「具体作业内容」。
2
AI 一键填写作业步骤 AI
点击「AI 辅助分析 / 一键生成步骤」。AI 判断内容是否完整、是否足以做 JSA：
  • 可行：直接输出 JSA 作业步骤草稿。
  • 不可行：给出推荐写法，申请人可一键引用后修改，再重新生成。
3
人工修改并保存
申请人确认或补充各作业步骤，点击保存。
4
AI 自动 JSA 分析 AI
保存后 AI 自动进行 JSA 分析，输出两部分结果：
  • 「作业中存在的危害和潜在事故后果（风险）」
  • 「风险控制措施」
输出格式：两列对照表，每个/每组风险项对应单个/多个控制措施，便于现场交底人员一一确认。
5
申请人确认
申请人对 AI 输出的风险项与措施项进行勾选 / 取消勾选修改，最终点击「确认」锁定 JSA 报告。确认后方可提交作业票。
可行性评估：该流程技术上完全可行。当前系统已有 analyzeWorkPermitRisk 接口，只需把「一次性建议」升级为「AI 一键生成步骤 + 自动分析 + 风险-措施两列 + 申请人勾选确认」，并在提交前强制校验 JSA 报告已确认。

八、一级安全培训（入厂校验）

项目常规作业票特殊作业票
申请阶段 仅填写预计作业人数；不强制培训已完成。
批准后 系统生成培训二维码并下发，承包商自行组织一级安全培训与考核。
入厂校验 作业人员入厂时校验一级安全培训是否通过；通过方可进场。校验未过者不能入厂。
记录挂在哪 挂在常规作业票上。根据入厂时关联人员，标注作业人员姓名，标注「培训合格」即可。 不挂整张票培训，仅校验直接作业人员与监护人培训在效期内。
是否硬拦截 finish/archive 否。培训在入厂时即已校验，进场人员均为合格者，故完工/归档不再单独卡培训。
与旧报告差异：此前把培训作为「提交/打印/finish/archive 硬拦截」，现已改为仅在入厂时校验，不阻断作业票状态流转。

九、安全交底

  • 挂载对象：常规作业票（一份）。不再按特殊票拆分。
  • 执行方式：全部线上。交底人员逐条勾选确认 + 承包商线上手写签名。
  • 内容来源：静态模板，但由 AI 高亮重点风险与措施（来自 JSA 结果，见 P2-1）。
  • 与特殊票的关系：特殊票沿用常规票这份交底；若常规票涉及多类特殊作业，交底模板中应能体现对应条目。
  • 流转作用：安全交底完成后，自动生成现场检查任务，推动作业票往下流转。
  • 移动端：安全交底与现场检查均内置在「现场作业台」，必须支持手机浏览与操作。

十、巡检与现场检查（进行中/暂停驱动）

核心规则：每日巡检不由 printedAt 决定，而由作业票的「进行中 / 暂停」状态决定。 每张作业票有「开始 / 暂停」按钮（申请人及管理员可操作）：
  • 进行中：该天需有 ≥1 条巡检记录，附照片（必选）。
  • 暂停：当天免巡检；EBoard 显示该票为「暂停」；暂停原因在审批进度面板中体现。
类型触发/录入强制关系备注
每日巡检 现场拍照上传（不再支持 OCR 回填；OCR 回填是早期纸质票回传场景需求，现已取消）。 硬拦截 自进入「进行中」起每个已过日历日 ≥1 条；缺记录须补充说明文字；照片必选。 挂在作业票自身（workPermitId）。受「进行中/暂停」状态驱动。
现场检查
（作业前安全措施落实）		 现场作业台（EOnsite）内置勾选项。 任务留存 安全交底完成后自动生成现场检查任务，作为执行记录留存；不单独硬阻断 finish/archive。 现场作业台需区分「安全交底」与「现场检查」两个标签页。
两类检查都作为任务放在「现场作业台」中，必须支持手机浏览与操作。

十一、邮件通知

邮件是强制生效功能，非可选。当前开发阶段关闭仅是为了防止误发，正式上线后必须开启。

触发点收件人内容
提交作业票 / 任一审批节点推进 下一环节审批权限人 含「同意 / 拒绝」按钮链接（token 48h、单次有效）。

十二、workCode 与二维码

常规作业票 approved 的瞬间，系统自动生成两样东西：6 位作业码（workCode）与一级安全培训考试二维码。二者不需要等到打印。

对象是否生成 workCode二维码作用失效规则

13.5 技术可行性（不备案、走系统分享面板）

你已明确：不愿意走 ICP 备案，因此微信内「原生一键转发」路线（需认证服务号 + 备案域名 + JS-SDK）不成立。改为：系统分享面板选微信，桌面端员工自行复制/下载图片转发。未来系统部署在阿里云 http://47.100.60.182:8010（端口可能变化）。

环境转发方式前置条件结论
手机系统浏览器（Safari / Chrome） 唤起系统分享面板，用户在面板中选「微信」 navigator.share({files:[png]})（Web Share API）；理想需 HTTPS。当前为 HTTP 公网 IP，部分手机浏览器 Web Share 受限，可降级为「下载图片」再手动发微信。 可用公网 IP 已解决「扫码打不开」问题。
桌面浏览器 员工自行复制图片 / 下载图片，手动粘到微信 — 降级无原生调起，靠下载图片。
微信内置浏览器 无法原生转发（无 JS-SDK） 需认证服务号 + 备案 暂不成立按你要求不做。
关于「阿里云 IP 能否解决分享二维码」：能。把 APP_BASE_URL 配成 http://47.100.60.182:8010 后，分享/邮件里的二维码就是外网可达地址，被转发者用手机扫码能打开。唯一遗憾是 HTTP 而非 HTTPS——部分手机的 Web Share API 与剪贴板写图会被禁用，届时退化为「下载图片」即可，不影响核心可用性。

十八、为什么原流程显得混乱

  1. 两套单据概念打架：原作业申请单与常规作业票是两张独立表，但业务上「申请单批准后就是作业票」，导致用户困惑、编号也两套。
  2. 承包商安全培训与一级培训混用：旧代码里培训名称不统一（曾与承包商安全培训混用），与现在「一级安全培训」口径不一致。
  3. 危险作业命名不规范：统称「危险作业票」容易让人以为 9 类都需特种证，实际只有 4 类强制。
  4. 打印被误当作流程开关：原设计把 printedAt 作为巡检起点、把 printed 作为现场执行前置，导致「不打印就不能干活、跨日就卡死」。
  5. 审批链与状态机错位：常规票需要区域负责人 + 承包商管理部门，但旧 evaluateRiskLevel low 只有 2 级；特殊票又混了风险分级 2/3/4 级。
  6. 邮件默认静默：enabled=false 时流程继续但无通知，用户以为发了实际没发。
  7. AI 能力未贯通：JSA 只是可选按钮、交底用静态模板、提交后复核未调用。
  8. 二维码语义重叠：作业码、环节码、考试码、分享码若都堆在详情页，现场人员分不清该扫哪个；各码「生成时机」原先分散在 approved / 首次打印 / 双审通过等不同节点。已在 12.1 统一。
  9. 系统无对外可达地址：APP_BASE_URL 未配置，邮件链接、扫码入口、分享短链共用同一个隐患——生成的都是打不开的地址。
  10. OCR 回填误残留：每日巡检的 OCR 回填是早期纸质票回传场景需求，与现行全线上流程不符。

附：状态机速查

常规作业票（GWP，即申请单）

draft →(提交) pending_review →(区域负责人+承包商管理部门) approved →(开始) 进行中 ⇄(暂停/恢复) 暂停 →(完工) finished →(归档) completed；另 rejected / voided。
说明：printed 仅为可选打印记录，不构成状态门；现场执行与每日巡检由「进行中/暂停」开关驱动。

特殊作业票（HWP/CSE/…）

draft →(提交，父常规票须 approved+) pending_review →(申请部门主管) ehs_reviewing →(EHS 工程师) reviewing →(工程部经理) approved → 进行中 ⇄ 暂停 → finished → completed；另 rejected / voided。

  • 固定审批流（无风险分级）：申请部门主管 → EHS 工程师 → 工程部经理。

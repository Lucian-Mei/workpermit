EHS 安全管理系统

一套完全自托管的环境 / 健康 / 安全（EHS）管理系统，覆盖隐患闭环治理、作业票全流程管控与组织权限管理，不依赖任何第三方表格服务。

7
隐患状态节点
10
作业票状态节点
RBAC
22 权限点 · 4 角色
2 核 4G
单台轻量部署

核心能力：隐患上报（含微信扫码免登录）→ AI 分析 → 派单 → 整改 → 验收；作业票申请 → AI 风险分析 → 特种作业证书 OCR → 审核 / 批准 → 打印两页 → 现场签字检查 → 归档；以及数据看板、组织权限、皮肤切换与一键备份。

系统架构

请求流向：用户 / 微信 → 前端（React）→ Nginx 反代 → 后端（NestJS + Drizzle）→ 数据库，外部按需接入 AI / OCR / 飞书。

用户端

管理员 / 安全员 / 审批人 / 员工；承包商微信扫码上报

前端

React 18 + Vite + Tailwind，运行时换肤 + 玻璃拟态

接入层

Nginx 反代，托管静态前端 + /api → 后端

后端

NestJS 10 模块化：认证 / 隐患 / 作业票 / AI / OCR / 看板

数据层

PostgreSQL 16（生产）/ PGlite 0.5.4（本地），DB_DRIVER 切换

外部集成

微信扫码 · AI 厂商 · OCR 厂商 · 飞书多维表格（可选备份）

完整可视化架构图见仓库根目录 ehs-architecture.html（浏览器直接打开）。

角色与权限

系统内置 4 个角色，可在「角色与权限」中增改；权限点形如 hazard:create，共 22 个。

角色权限要点
系统管理员 admin全部权限，含系统设置与备份
安全员 safety隐患派单 / 验收、作业票审核、现场检查
审批人 approver批准作业票（含特种作业）
普通员工 employee上报隐患、提交自己的作业票申请

隐患管理

覆盖「上报 → 派单 → 整改 → 验收」闭环，共 7 个状态节点，可随机停留在任意环节。

待分配 → 已派单 → 已整改 → 部门确认 → 已验收 → 已驳回 / 已取消

支持 AI 智能分析隐患等级与整改建议；微信扫码上报的隐患在「只看我的上报」中可查看历史。

作业票管理

申请 → AI 风险分析 → 特种作业证书 OCR → 审核 → 批准 → 打印两页 → 现场签字检查 → 归档，共 10 个状态节点。

草稿 → 待审核 → 审核中 → 已批准 → 已打印 → 已完成 → 已归档 已暂停 已驳回 / 已作废
特种作业

必须上传作业证，系统 OCR 识别（阿里云）；识别不了转人工确认。需审批人额外批准 + 现场检查。

打印模板（两页）

第一页作业票正文；第二页证书附件（照片 + OCR 信息，无需人员填字）。打印后现场张贴签字。

作业申请单

组织与区域

部门、员工账号、作业区域均在系统内集中维护，是隐患与作业票的下拉数据源。

部门

维护负责人 / 协调人 / 联系电话，可设部门管理员

员工账号

拼音账号 + 系统下发密码，归属部门 / 区域，可禁用

作业区域

楼栋 / 楼层 / 责任部门，作为上报与作业票的地点下拉

微信扫码免登录上报

「隐患随手拍」页面 /anonymous 为公开地址，无需登录即可上报。

现场扫码上报

扫码后填写姓名即可上报，可拍照上传；登录后在「只看我的上报」查看历史。

安全防刷

接口带 IP 限流（1 小时最多 20 条 / 40 次上传）。打印 http://<服务器IP>/anonymous 张贴现场。

皮肤与主题

系统支持运行时皮肤切换，无需刷新即可即时生效，偏好本地保存。

明暗模式
明亮 / 暗色

暗色模式采用精炼石板灰，无霓虹，长时间盯屏更舒适。

强调色
蓝 / 绿 / 青 / 紫 / 琥珀 / 靛

主色、图表首色、链接等随之变化，所有对比度调校至 WCAG AA。

材质 / 圆角
实色 / 柔和 / 玻璃拟态 · 4 档圆角

玻璃拟态带柔光反射与背景虚化，立体而不喧哗。

字体 / 密度
无衬线 / 圆体 / 等宽 · 紧凑 / 适中 / 宽松

适配不同屏幕与阅读习惯，密度切换改变卡片内边距与行高。

本帮助文档顶栏即内置同样的主题切换，可实时预览不同皮肤效果。

备份与飞书

数据完全自托管，备份一键完成；飞书仅作为可选同步目标。

下载备份

系统设置 → 数据备份 → 立即备份并下载。优先 pg_dump SQL，无则退化为 JSON。

飞书同步（可选）

填好 FEISHU_* 四项后，点「同步到飞书」推送统计到多维表格；留空则只提供下载。

部署上线

Docker Compose 一键部署，单台 2 核 4G 轻量服务器即可承载。

cp .env.example .env   # 改 JWT_SECRET / DB_PASSWORD / AI_API_KEY / ALIYUN_OCR_*
chmod +x deploy.sh
./deploy.sh              # nginx + 前端 + 后端 + PostgreSQL
访问

http://<服务器IP>（nginx 80）· API /api

数据持久化

数据库在 ehs_pg_data 卷、上传在 ehs_uploads 卷，升级镜像不丢数据。

HTTPS 将证书放到 nginx/certs/ 并打开 nginx.conf 末尾 443 server 块即可（可选）。

常见问题

Q：表结构怎么更新？

改 schema.ts 后，开发期跑 npx drizzle-kit push，生产用 drizzle-kit migrate。

Q：AI / OCR 没配能用吗？

能。相关按钮提示「AI 暂不可用」，不影响核心流转；审核人员可人工完成分析。

Q：想加新作业类型？

在后端 WORK_PERMIT_TYPES 加一项（标是否特种作业 / 需证书），前端 constants.ts 同步一条。

Q：想加新角色 / 权限？

「角色与权限」页面新建角色并勾选权限点；新权限点需在 PERMISSIONS 登记。
